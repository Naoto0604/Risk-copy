「4」が**Issue #4：Webセキュリティ基本診断エンジン**のことなら、ここからがRiskTraceの本体やな。

ただ、いきなり全部作るんじゃなくて、**Crawlerが取得したURLを `checks.py` に渡して、各チェック結果を返す**構造にする。

## ファイル構成

```text
RiskTrace/
├── app.py
│
├── scanner/
│   ├── __init__.py
│   ├── crawler.py
│   └── checks.py        ← ここを作る
│
└── templates/
    ├── index.html
    ├── scanning.html
    └── result.html
```

### `checks.py` の役割

```text
Crawler
  ↓
発見したURL
  ↓
checks.py
  ↓
セキュリティチェック
  ↓
Findingを返す
```

最初は**パッシブなチェック**だけにする。

---

# まず作る診断

最初のバージョンはこの5つでええ。

### ① HTTPSチェック

```text
http://example.com
       ↓
⚠ HTTPSが使用されていません
```

### ② Security Headers

例えば、

* Content-Security-Policy
* X-Content-Type-Options
* Strict-Transport-Security
* Referrer-Policy

などが設定されているか確認。

### ③ Cookie属性

Cookieに、

```text
Secure
HttpOnly
SameSite
```

が設定されているか確認。

### ④ Server情報露出

レスポンスヘッダーに、

```text
Server: Apache/2.4.xx
X-Powered-By: PHP/8.x
```

などがないか確認。

### ⑤ エラー情報露出

エラーレスポンスに、

```text
Traceback
PHP Warning
SQL error
```

などの詳細情報が出ていないか確認。

# `checks.py` の構造

例えばこんな感じ。

```python
def check_https(url):
    pass


def check_security_headers(response):
    pass


def check_cookies(response):
    pass


def check_information_disclosure(response):
    pass


def check_error_information(response):
    pass
```

そして最後に、

```python
def run_checks(url, response):
    findings = []

    findings.append(check_https(url))
    findings.append(check_security_headers(response))
    findings.append(check_cookies(response))
    findings.append(check_information_disclosure(response))
    findings.append(check_error_information(response))

    return findings
```

みたいに**全部の診断をまとめて実行する関数**を作る。

---

# Findingの形式を最初に決める

ここ結構重要。

診断結果をバラバラの文字列にせず、最初から統一する。

例えば、

```python
{
    "type": "SECURITY_HEADER",
    "severity": "MEDIUM",
    "title": "Content-Security-Policyが設定されていません",
    "url": "https://example.com",
    "description": "CSPが設定されていないため..."
}
```

みたいな形。

これにしておけば後で、

```text
checks.py
    ↓
scoring.py
    ↓
correlation.py
    ↓
attack_path.py
```

と渡せる。

**RiskTraceの後半機能を作るためにも、ここはちゃんと設計した方がいい。**

# そして `app.py`

Crawlerと診断を繋ぐ。

イメージは、


---

## ⚠️ ここで一つ重要

**#4ではSQL InjectionやXSSを実際に攻撃して検証するところから始めない方がいい。**

まず、

> HTTPレスポンス・HTML・Cookie・ヘッダーなどを**受動的に分析する診断**

を完成させる。

これなら実装もしやすいし、誤って第三者サイトに攻撃的なリクエストを送る設計にもならない。

その後、**自分たちで用意したテスト環境**を使って、必要なアクティブチェックを安全に追加していく。

### #4の完成形

```text
URL
 ↓
Crawler
 ↓
ページ発見
 ↓
HTTPレスポンス取得
 ↓
┌─────────────────────┐
│ Security Checks     │
│                     │
│ HTTPS               │
│ Headers             │
│ Cookies             │
│ Information Leak    │
│ Error Disclosure    │
└─────────┬───────────┘
          ↓
      Findings
          ↓

```

**まず `checks.py` を作って、①HTTPS → ②Security Headers → ③Cookieの順に実装**するのがええで。
この3つが動けば、残りは同じパターンで増やせる。
